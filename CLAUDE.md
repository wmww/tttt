# tttt
tttt is a work-in-progress TypeScript reimplementation in C.

## Objective
The project's focus is performance, ideally beating the new typescript-go. But we need to fully support the TypeScript language first. That's what you're working on today.

The oracle is TypeScript 7.1 (the 7.1.0-beta, `v7.1-beta` = 3e923636; `thirdparty/ensure-typescript.sh`: tsgo's Go sources and native test suite in `thirdparty/typescript`, its CLI at `thirdparty/typescript/built/tsc`). The test suite, libs, probes (`filetest.sh`/`tscbaseline.sh`/`mutate.py`, through `scripts/tsgoprobe.sh`), the sweeps' tool (`tttt-oracle`, `test/oracle/README.md`) and every cached expectation are tsgo 7.1's.

Tests are the oracle, but not the true end goal. Special casing tests, or getting a few more tests to pass under an architecture that is fundamentally flawed doesn't help anyone. Keep the big picture in mind.

This is a massive project and I'm giving you and all the other agents a lot of autonomy. Use it wisely.

## Agents directory
Keep notes for future agents in `agents/`, including:
- `agents/vision.md` - the goal, the state (numbers with their date and commit), the direction and why, and the standing decisions (what was tried and withdrawn, and the reason).
- `agents/todo.md` - the live list of directions and ideas, roughly ordered, each a short paragraph: what, why, what is known, where the numbers are.
- `agents/coordinator.md` - how a coordinator runs the work: decomposition, briefs, the merger, judging results.
- `agents/handoff.md` - exists only between coordinators: written when the human asks a coordinator to wind down (in-flight work, decisions, what to re-check, worktrees and branches); the next coordinator reads it, acts on it and deletes it.
- `agents/notes/*.md` - design knowledge a future agent needs that isn't in `documentation.md`, `measurements.md` or the code (what was measured, decided against and why).
- `agents/measurements.md` - the latest numbers of each kind, with the command, the box, the date and the commit.
- `agents/hacks.md` - contains a comprehensive list of hacks, workarounds and other suboptimal-but-working aspects of the code. Prefer function names over line numbers for stability. Add when writing a hack, or when discovering code that seems sus. Hacks don't need to be immediately addressed, they're meant for discovering and fixing antipatterns.
- `agents/triage.md` - a dumping ground for uninvestigated bugs, potential long-term problems, papercuts, ideas, and anything else an agent doesn't want to deal with at the moment, but a future agent should sort out.
- `agents/bugs/*.md` - reports of known issues, by area; every bullet ends with a status tag (`[open]`, `[design]`, `[text]`, `[tsgo]`, `[fixed COMMIT]`...: `agents/bugs/README.md`), and a fix flips its entry to `[fixed COMMIT]`.

`agents/` should be committed to git just like code. Create, edit and delete files in `agents/` freely. Remove files that are no longer relevant (eg solved bugs, finished notes) and clean up confusing and unimportant references to previous state. "plan N" in code comments and scripts is a historical tag: `git show af936072c:agents/plans/` lists the plans, which were deleted on 2026-10-22.

## Workflow
- One coordinator works in conversation with the human: it receives work from them and runs sub-agents for as long as the work lasts (`agents/coordinator.md`). Workers run in worktrees (`scripts/worktree.sh NAME`), get a narrow brief and report back; a merger brings their branches into `main` and runs the oracles. The coordinator owns `agents/` and the commits. There is no strict chain of command: anyone may write code or edit vision.md when it's the most useful thing to do.
- If you're a toplevel agent without additional instructions, read `agents/handoff.md` if it exists, then vision.md and todo.md.
- When you fix a divergence found outside tsc's suite (corpora, sweeps, a probe), add a cut-down repro to `test/cases/` (`scripts/owntests.sh` for its baselines) that fails without the fix.
- Commit messages should be a summary of what you did and what happened, generally a paragraph or two. Include doubts and things that went wrong, these will be helpful later.
- Workers don't commit `test/baseline_results.ts` (parallel branches conflict on it): the coordinator saves it per batch. `scripts/land.sh BRANCH [--no-gate] [-p REGEX] [-k]` lands a worker's branch from the main tree: refuses a branch that touches it, rebases on a detached HEAD (conflicts abort), runs `scripts/quickgate.sh`, fast-forwards main, pulls --rebase and pushes.
- When a piece of work lands: save `scripts/fasttest.sh -s`, check and record instruction counts (`scripts/instrcount.sh`), `git worktree list` shows only the repo (every worktree's commits merged or deliberately dropped, said in the commit message, its branch deleted), your /tmp scratch (dumps, probe trees, `go-build*`) is deleted, then pull --rebase and push. `main` is the branch; worktree branches are short-lived.
- Any agent may "fail", if that's best for the project. If half way through a piece of work you discover it takes the wrong approach, stop and report that, with the reason, rather than pushing through.
- Feel free to build tools and scripts, and share them with future agents if they're generally useful. The workflow of this project was originally optimized for humans, so the tooling might need adapting to be optimal for agents.
- Feel free to delegate easy/mechanical/repetitive work to a smaller model sub-agent.
- Disk is shared and filled up once (2026-10-14: a 50 GB Go build cache, now capped by `ensure-typescript.sh`).
- Sub-agents running in parallel with you or each other must not experiment in the shared tree: give them a worktree (`scripts/worktree.sh NAME`: `/tmp/wt-NAME` with the untracked `thirdparty/` checkouts symlinked in). The symlinked corpora are shared: probes go elsewhere. Parallel agents must never `git stash` (shared by all worktrees) nor wait on `pgrep -f` patterns (they match each other's builds).
- Be conservative with Fable sub-agents, don't fan out to many of them.
- If you're using Anthropic models: Opus for anything needing judgment (checker semantics, perf analysis, debugging); Sonnet is fine for mechanical refactors and long iteration loops with a clear oracle. If only Opus is available, ignore stuff about choosing a model.
- You may edit this file (CLAUDE.md; AGENTS.md is a symlink to it), but keep it compact and meaningful. Favor other files which can be read as-needed for all but the most important content.

## Development Scripts
You will use scripts to help you run tests, but some scripts and options are more useful to AI agents than others. All scripts live in `scripts/` (run them from the repo root: they `cd` there themselves), automatically compile the code in src before running tttt, and abort if there are any compile errors. The main scripts you will use are:

- `test/cases/tttt*.ts`: tttt's own regression tests (tsc-suite style headers), run by `scripts/fasttest.sh` with the suite against tsgo's baselines checked in at `test/baselines` (`scripts/owntests.sh [FILE...]` regenerates them)
- `scripts/fasttest.sh --summary`: Shows which new tests pass and which new tests fail, compared to the saved results (`test/baseline_results.ts`). **Save them with `scripts/fasttest.sh -s` before you commit** (`scripts/passcount.py` prints the totals of the saved file), or the next agent's summary is polluted by yours
- `scripts/test.sh -f specificTestName -d`: Shows the detailed output of a specific failing test, runs under valgrind, so may fail with a useful message if there are memory errors.
- `scripts/test.sh -f specificTestName --sym`: Shows only symbols for a given test, flag can also be `--err` or `--typ`
- `scripts/filetest.sh path/to/file.ts -d`: Run a test on a file that is not part of TypeScript's existing test suite. This is useful for better understanding how both tttt and tsc work in a simplified case that may not otherwise be tested. You can create any typescript files you want and use this command on them. Prefix with `FAST=1` to use the release build without valgrind (seconds instead of a minute)
- A test file with `// @target: es5,es2015` (any boolean/enum option with several values) is one test per configuration, named `name(target=es5)` like tsc's baselines. `-f name` runs all configurations of it. Compiler options live in `CompilerOptions` (`src/compiler_options.h`), read through `compiler_options()`
- `-f` takes a regex that must match the whole test name (`-f '^async.*'`, not `-f async`), or `-f @names.txt` (one exact name per line; long regex alternations silently match nothing). If a full run gets OOM-killed or hangs, some newly reachable checker path is running away: bisect with `(ulimit -v 6000000; ./release/baseline_tests -f '^a.*')` per letter
- `scripts/failstats.py`: Runs the whole suite (~25s) and reports *why* tests fail in aggregate: checker `log_error`s, missing/spurious diagnostic codes, nearly-passing tests. `--syntax` lists the syntax shapes the parser wrongly rejects, `--code TS2322` lists the tests affected by a code, `-f regex` restricts it, `--jsx` to the tests with JSX. Use it to pick work that moves whole categories. Latest numbers are in `agents/measurements.md`
- `scripts/unimplemented_codes.sh`: After `scripts/failstats.py`, the missing diagnostic codes that `src/` never mentions (checks tttt doesn't have at all), with counts and messages
- tttt's CLI is a drop-in `tsc --noEmit`, and a drop-in `tsc` where the config only emits declarations (`emitDeclarationOnly`: it writes the `.d.ts` and `.d.ts.map` files): tsc's output formats and exit codes, nothing else on stdout. **Tools running tttt on shared checkouts pass `--noEmit` with `-p` and `--no-write` with `-b`** (the `-b` corpora emit declarations). Scripts parse its `--pretty false` output with `scripts/tscformat.py`; `--keep-going` (check past gating errors) is tttt's own, for tools that want types anyway (expecttypes, checkerdiff); the diagnostic oracles compare against tsc's CLI and run without it; `--no-rerun` (env `TTTT_NO_RERUN=1`) skips the one-checker recheck after a history-dependent diagnostic (limits, circularities: agents/notes/one_checker_rerun.md), faster but K-dependent there; `--rerun` is the default
- `scripts/realworld.py`: Runs tttt on a real project (TypeScript 6's own `src/compiler`, 193k lines, the `TypeScript6` corpus; through its tsconfig) and groups what it reports by code and by offending token, then compares it with tsc's cached diagnostics there (`test/corpora.tsc.jsonl`, `--tsc` regenerates a corpus' entry): every spurious or missing one is a tttt bug; this is the second oracle next to the test suite. `--corpus type-fest|valibot|react|nest|webpack|zod|xstate|drizzle|vue|effect|vscode|excalidraw|tanstack-router|tsc-src|typescript-eslint` checks the other pinned corpora (vscode: 1.39M lines, the scale one) (`thirdparty/ensure-corpora.sh`; the last two with `-b` on a solution config); `zod-root` and `webpack` aren't clean under tsc either
- `scripts/clidiff.py [--corpora] [-f regex] [-k KIND] [-v] [--last]`: tttt as a drop-in tsc: `tttt -p P --noEmit --pretty false`'s whole stdout (message text, elaboration chains) and exit code against tsc's, cached (`text` in the source sweep's and the corpora's tsc caches, `--tsc` regenerates the stale ones), on every corpus and source sweep project (~5 min; `--corpora` ~1.5 min); `text` mismatches bucketed by first differing part (header type printing, chain). `--live [--pretty] [--sample N]` runs tsc now; `--emit`: the `emitDeclarationOnly` projects as they are, both CLIs emitting in a bwrap overlay sandbox, the written trees compared too
- `scripts/tttt_run.py`: **the one way an oracle runs tttt** (`tttt_run.run(cmd, cwd, timeout, mem_gb)`): RLIMIT_AS of mem_gb plus 0.5 GB per thread (tttt reserves address space per thread: 4 GB fails at the defaults), a timeout, the build binary frozen (copied at its first run, so a rebuild mid-run never swaps it), and a status that keeps `timeout`/`killed`/`memory` apart from crashes (`exit N`, `signal N`) and from differences; every sweep, kdiff, buncases, dtsdiff, expecttypes, flagflip and clidiff use it: a new oracle must too
- `scripts/projdiff.py PROJECT [--copy] [-- OPTIONS]`: **one project, tsgo against tttt, safely**: tsgo through tttt-oracle (never a plain `built/tsc -p`, which writes .tsbuildinfo into shared checkouts and then skips checking), tttt at its defaults and at `--checkers 1` in a read-only sandbox; prints the (file, line, code) each side alone has, a K-dependence, and whether the whole output is byte-identical (else its first differing line); `--copy` on reduce.py's scratch copy
- `scripts/sourcescheck.sh [--save]`: the shared source checkouts' integrity in a second (sha256 of 400 sampled node_modules/@types files, `test/sourcescheck.txt`; their dependency files are hardlinked across repos, so one stray write corrupts many): sourcesweep.py and dtsdiff.py warn first when it fails; `--save` after ensure-sources.sh installs
- `scripts/sweep.py [-f regex]`: the breadth sweep: tttt on every DefinitelyTyped package (~8600 small projects incl. the versioned `types/X/vN`, ~2-5 min) against tsc's cached diagnostics (`test/sweep/`), crashes first, then mismatches ranked by root cause across packages (`-k KEY` instances, `--names VERDICT`, `--last` reuses the run). The third oracle: run it next to the corpora after checker changes
- `scripts/npmsample.py --seed S [-N 50]`: the fresh measure (agents/notes/npm_sampling.md): a seed's random npm packages' GitHub repos (TypeScript ones), cloned and installed under thirdparty/npmsample/S (scripts off, a `tsconfig.bench.json` tsgo 7.1 accepts), the first N sane ones checked by tsgo and tttt; per-project table, byte-identical and clean-agreement percentages, `--threads 1` persistence. `--large` (sample and setup): the biased-to-big mode, random large GitHub repositories (`reposearch.py large`), up to `--per-repo K` workspace packages each as projects (npm_sampling.md "Large mode"). Subcommands `sample`/`setup` (resumable)/`compare [--last] [-k CODE]`/`clean [--all]`; the batch deletes matching clones at the end. `compare` stores per diverging project a `diff` list (up to 30 {side, code, key = message skeleton, file, line}) so a deleted clone keeps its fingerprint; `rank [--min N] [--json]` aggregates every seed's records by (side, code, key) (code only for older records), ranked by projects then seeds, 3 examples each, status open/repro/fixed (repros.tsv, agents/bugs/npmsample*.md). Records in test/npmsample/S.*
- `scripts/buncases.py [-f regex] [--show ID]`: bun's differential check cases (`test/buncases/`, 2418 small projects on which `bun check`, another tsgo reimplementation, once disagreed with tsc): each written to /tmp and checked like bun's runner does (`tsc`/`tttt` in the case's directory, `-b` for some), tsgo cached, tttt at its defaults and at 1 and 4 checkers (a difference is K-dependence); byte-identical, (file, line, code) match, then spurious/missing ranked by root cause, crash sites, text-only buckets (`-k`, `--names`, `--last`; ~30 s)
- `scripts/sourcesweep.py [-f regex]`: the source sweep: tttt on every `tsconfig*.json` (bases others extend aside) of ~150 real repositories (`test/sourcesweep/repos.txt`, installed by `thirdparty/ensure-sources.sh` into `thirdparty/sources`, symlink it in worktrees) against tsc's cached diagnostics (~5 min; `--sample 4` a fixed quarter), crashes first, then mismatches ranked by root cause across repos (`-k KEY`, `-k=-TS6305` for a missing one, `--names VERDICT`, `--last`, `--tsc-new` after adding repos; `--defaults [--runs N]`: tttt at its default threads and checkers, verdict `varies` when runs differ; ~4 min with `--sample 4`). The fourth oracle: real application and library code with real configs. `--build`: every repo's solution roots (configs with `references`), tsgo `-b --force` sandboxed against `tttt -b` (~3 min; its own cache)
- `scripts/reduce.py --project DIR --keep REGEX [--tttt-has|--tsgo-has] [--files GLOB] [--from COPY]`: **the repro reducer**: copies a real project's program (packages and pnpm/workspace links resolved into regular files) into /tmp/reduce-*, runs tsgo and tttt there in a bwrap sandbox, and cuts files and lines while a differing diagnostic matching REGEX stays; writes a test/cases-ready `case.ts`. Never write your own reducer over shared checkouts
- `scripts/expecttypes.py [-f regex] [-k KIND]`: the types oracle at breadth: DefinitelyTyped's 69k `// $ExpectType` assertions, tttt's printed type of each asserted expression (`tttt --expect-types SPANS`) against tsc's (cached), mismatches bucketed by kind (union order, we-any, ...); ~30 s. Run it next to the sweep after checker or printer changes. `scripts/expectprobe.py DIR [--reduce FILE TEXT]` runs one cut-down project (a tsconfig listing the package's .d.ts by absolute path plus a test file of your own) through both sides and deletes chunks of FILE while TEXT stays among the mismatches
- `scripts/dtsstats.py [-f regex] [-k BUCKET] [--names] [--last] [--js]`: the suite's `dts` component (declaration emit; `baseline_tests --dts` shows its diffs): failing tests bucketed by first differing line; `--js` the tests with JavaScript inputs (`baseline_tests --dts-js`; `--dts` shows the others')
- `scripts/dtsdiff.py [-f regex] [-k BUCKET] [--show PROJECT [FILE]]`: declaration emit at breadth: tsgo's `.d.ts` and `.d.ts.map` files (hashes cached in `test/dts/`, `--tsc` regenerates; its texts kept in /tmp) against what `tttt -p` writes (both in a bwrap sandbox, outputs redirected to /tmp) on the `-p` corpora and every declaration-emitting source sweep project, byte for byte, mismatches bucketed by first differing line or mapping (`--names`, `--sample N`, `--last`); `--tsc-single` caches `tsgo --singleThreaded`'s hashes for the last run's mismatching projects, whose files tttt writes like it are then counted apart (tsgo's own checker split); `scripts/mapshow.py [-s] A.map [B.map]` decodes and compares maps
- `scripts/flagflip.py [-c corpus] [-F flag] [--cells] [-k KEY]`: missing diagnostics on real code: every `-p` corpus rechecked with a flag tsc then reports thousands of diagnostics under (noUncheckedIndexedAccess, exactOptionalPropertyTypes, the non-strict modes, ...), against tsc's output cached in `test/flagflip` (`--tsc` regenerates stale cells), ranked by root cause (`TSa->TSb`: tsc's code a reported as b). Run it next to the corpora after checker changes (~80 s)
- `scripts/mutate.py [-n N] [--seed S]`: mutation testing: one small mutation (operator in the name) to each of N passing single-file suite tests, tsc's baselines cached in /tmp/mutate, mismatches bucketed by first difference (`-k KEY` lists, `--show NAME` diffs one, `--recheck` reruns only tttt). Finds missing checks the clean oracles can't; ~90 s for 8000 mutants
- `scripts/scenarios.py [-f regex] [-v]`: project references and `-b`: replays the first command of tsc's own tsbuild/tsc project-reference baselines (a virtual tree written to /tmp) and compares (file, line, code); known divergences are skipped with a reason. `tttt -b [PROJECT...]` checks a solution like `tsc -b` (referenced projects are read through their emitted declarations, `--builders J` of them at once, output in build order), `scripts/realworld.py --corpus tsc-src` runs it on TypeScript's `src`
- `scripts/kdiff.py [-k K] [--dt] [-f regex]`: tttt's output at `--checkers 1` against K (default 16) on the source sweep or DT: tsgo's output is checker-count independent (nearly: sequelize/packages/core's TS7022 differs in tsgo too), so a project it lists is almost always a tttt bug. The sweeps run tttt at its default checker count; `-k 1 -m 0` compares against a fresh checker per file (`--checker-memory 0`: checker recycling; the CLI's default `--checker-memory` is a quarter of RAM; plain `-k 1` is refused, one checker against itself); timeouts and memory kills are listed apart, never as differences
- `scripts/perfsweep.py [-f regex] [-j N] [--sample N] [--corpora] [--last]`: perf at breadth: tttt `--checkers 1` against tsgo `--singleThreaded --extendedDiagnostics` on every source sweep project tsgo checks (tsgo's side cached in `test/perfsweep/`, measured cold: tsc --noEmit reads and writes incremental projects' .tsbuildinfo otherwise): check-time, types and RSS ratio distributions, projects ranked by **types ratio** (machine-independent: above ~1.5 is a missing cache or a runaway) and by time. ~1.5 min at `-j 4`, times inflated under load; `--defaults` also times tttt at its default threads and checkers against its K1 run (recycle thrash)
- `scripts/perfshape.sh -p P [--bun PATH]`: a redacted shape report of one project (numbers only: files and bytes by kind, checkers and threads chosen, per-phase wall, CPU and cores busy, the checkers' span against the per-file check sums, idle tails, the costliest file's share, the K1 run, bun and tsgo next to it), for the human to paste from private code
- `scripts/scaleprobe.py [-k KIND] [-n N] [--emit]`: synthetic single declarations/blocks of N members/statements/elements (object literals, classes, interfaces, unions, `&&` chains...) timed against tsgo: finds quadratic paths no corpus is big enough to show (~3 min; `--emit` with declaration emit and maps)
- `scripts/quickgate.sh [-p PROJECT_REGEX] [-k] [--vs-main] [--no-instr]`: **the standard gate before a commit lands**, one PASS/FAIL line each and exit 1 on any failure: the suite (0 newly failing; `--vs-main`: against the results of the main this branch started from, so "new" is this change's alone), realworld on tsc/zod/drizzle (0/0), instrcount drizzle zod (release/tttt against that main's release build, no rise over 2%; `--no-instr` skips it); `-p` adds sourcesweep and kdiff -k 16 on the touched projects, `-k` threadcheck and checkerdiff; in parallel under nice, ~3 min, logs in /tmp/quickgate-*
- `scripts/abbuild.sh REV [--patch F|--revert C] [--fast|--suite-results|--dir]`: **the "before" side of an A/B**, built out of tree (a `git archive` export in /tmp/abbuild-TREE, cached by tree hash, locked) and its binary's path printed; never touches your release/ or index (`git checkout C -- path` stages the old file: don't). Also the frozen binary to run a long oracle on while you keep rebuilding; `--clean` removes builds unused for a day
- `scripts/oracles.py [--quick]`: every oracle above (suite lost/gained against HEAD, every corpus, sweep, `$ExpectType`, flagflip, perfsweep, clidiff, dtsdiff...), one line each (~8 min, `--quick` suite, corpora and their clidiff ~2 min); saves the suite's results like `-s`
- `scripts/bugcount.py [--save] [--run] [--list TAG] [-v]`: the known-correctness-bugs headline (open root causes, designs, text-only, tsgo artifacts excluded: the tags of agents/bugs/*.md and triage.md), the symptom counts of the saved suite results and every oracle's `--last` cache (this tree's, else main's or the merger's wt-gate), and the oracles' root-cause keys no entry mentions (unwritten bugs); seconds; `--save` appends the dated line to measurements.md
- `scripts/resultdiff.py [--lost|--gained] [--names]`: After `scripts/fasttest.sh -s`, which test components changed compared to git HEAD's saved results (plain text, unlike the coloured `--summary`). `scripts/failstats.py --code X` reuses the last full `scripts/failstats.py` run: rerun that first
- `scripts/displaydiff.py`: After `scripts/failstats.py`, why tests that pass their errors fail the types component (`--symbols`: the symbols component): mismatching lines bucketed by mechanism (union order, `typeof` reuse, `import()` qualification, `T_1` renaming, class expressions...) with examples (`-k kind`, `-f regex`, `--names`), and how many tests each kind alone fails (the ranking to work from). `--fine` splits the catch-alls (`other`, `we-any`...) into shape/annotated-node and ranks tests by their first differing line (the queue for silent type differences)
- `scripts/errtextdiff.py`: After `scripts/failstats.py`, the tests with the right codes at the right positions but other text: the first differing part of each diagnostic (header type printing, elaboration chain, related info, underline) bucketed, with tests fixed by one kind (`-k kind` prefix, `--names`, `--coarse`)
- `scripts/jsstats.py`: After `scripts/failstats.py`, the JS tests (bugs/js.md): how many pass, and the failing ones by the features they need (CommonJS, expandos, JSDoc tags, JS syntax diagnostics...), with cumulative "could pass" bounds; `scripts/jsstats.py 1cjs,3jsdoc` lists the tests with exactly those categories
- `scripts/syntaxstats.py`: After `scripts/failstats.py`, the TS tests whose *parser* diagnostics differ from tsc's, by where they diverge (A-E, M) and by mechanism cluster (recovery, permissive grammar, lexical); `--list CLUSTER` shows first differing errors with source lines, `--names CLUSTER` just names
- Don't `pkill -f <pattern>` in the same command line that contains the pattern (it kills your own shell); find the PID with `pgrep` first
- `scripts/findcrash.py [prefix]`: When the release suite dies (crash, hang, memory runaway: it runs each probe under `ulimit -v` and `timeout`), bisects on test name prefixes and prints the tests responsible
- `TTTT_DEBUG_RELATE=1` logs every top-level type relation query (source, target, ids, result), handy with `scripts/run.sh` or `./release/tttt` on a small file
- `TTTT_DEBUG_RELATE_NESTED=1` logs every nested pair too (depth, result, whether it made a variance measurement unreliable), printed when each finishes; `TTTT_DUMP_VARIANCES=1` prints measured variances (1 co, 2 contra, 3 bi, 4 independent, +8 unreliable, +16 unmeasurable)
- `TTTT_VARIANCE_CENSUS=1` prints a `VC` line per variance measurement (checker, subject, values, clean by the taint counter, deep cuts, types made); `scripts/variancecensus.py -p P [-k K] [--subject NAME]` compares K1 with K checkers: duplication, clean/tainted per subject, value disagreements
- `scripts/reentrytrace.py P... [--trace] [--tsgo-only -j N]`: what tsc re-enters while in flight below a resolution barrier (calls, variance), nested call results, members re-resolved (an instrumented tsgo built into /tmp) against tttt's `TTTT_DEBUG_REENTRY=1` events, per file:line (agents/notes/reentrancy.md)
- `scripts/variancetrace.py PROJECT [--block NAME]`: variance measurements against an instrumented tsgo (built once into /tmp, the shared checkout untouched): which stored variances differ, and with `--block` both sides' comparisons inside NAME's measurement (`TTTT_DEBUG_VARIANCE=1` is tttt's side of the log)
- `scripts/tsgotrace.py CODE FILE|PROJECT [--suite] [--funcs f1,f2]`: **where tsgo reports a diagnostic**: tsgo instrumented through an overlay (built once per tsgo commit and patch set into /tmp/tsgotrace-*), the Go stack at the creation of every diagnostic with code CODE, kept or not, through tttt-oracle (a project, or a file with options after `--`) or with `--suite` tsgo's own test runner (header-style tests; the harness can differ from the CLI); `--funcs` also a stack at each entry of the named checker functions. `scripts/overlaycheck.sh`: every overlay (test/oracle, reentrytrace, variancetrace, tsgotrace) still applies and compiles: **run it at every re-pin**
- `scripts/fieldcensus.py STRUCT... [-F FIELD|--eq|--keys] [-v]`: how C structs are used across src/, from clang's AST (exact): reads/writes per field, `T *` compares and `T *` used as keys, by function (agents/notes/type_graph_design.md's census)
- `scripts/reltrace.py FILE|PROJECT [--filter TEXT] [-- OPTIONS]`: every relation tsgo checks (an instrumented tttt-oracle built once into /tmp), each nested comparison's source, target, result and depth, next to tttt's `TTTT_DEBUG_RELATE_NESTED` for the same input, with the first divergence printed: where an assignability verdict parts (agents/notes/instrumenting_tsgo.md)
- `TTTT_RESOLVE_TIMES=1` times name resolution's steps (declare, link, the walk...), `TTTT_LOAD_POOL_STATS=1` the load pool's
- `bench/timeline/` (LD_PRELOAD, `TIMELINE_OUT`, `TIMELINE_ALL=1` for blocked threads too): every thread's CPU, run-queue wait and stacks per phase (`timeline.py OUT --skip @libc`): where the pool idles and what the main thread does meanwhile; `bench/sampler/` is the main thread's alone
- `TTTT_FILE_TIMES=1` prints each checked file's check time (and its unused/declaration pass) on stderr: `sort -k3 -n -r` finds the file a slow project spends its time in, and when each checker finished it (a timeline: which file is a parallel run's critical path)
- Deferred function bodies (documentation.md "Deferred bodies"): the CLI parses and walks outermost TypeScript function bodies only when a checker needs them (`--no-defer-bodies`: up front), the harness too (`baseline_tests --no-defer-bodies`: up front; `scripts/oracles.py` runs both); `TTTT_DEFER_STATS=1` prints what was deferred, materialized and rerun
- `scripts/taintstats.sh [--lenient] [--cleandiff] -p P`: the shared graph's taint prototype (agents/notes/shared_graph.md) (a `-DTTTT_TAINT` build in /tmp): which lazily computed results are clean (publishable to a shared graph) per kind, and with `--cleandiff` whether two histories (a fresh checker per file) agree on them; `--print-types --kind K` describes one kind's mismatches. Rerun on drizzle, excalidraw, zod, effect and vscode after a change to the shared graph
- `TTTT_CHECK_ONLY=substring[,substring...]` checks only the files whose path contains one, in a fresh checker (the rest of the program loaded): reproduces at one checker an output that depends on which file a checker saw first (`scripts/kdiff.py`)
- `TTTT_DUP_CENSUS=1` prints cross-checker duplication (each checker's types and relation entries by structural fingerprint: copies vs distinct, by class, per checker); with `TTTT_DUP_DUMP=F --checker-memory 0` each file's type set, `TTTT_DUP_GRAPH=F` the import graph and `TTTT_DUP_DEAL=F` a forced checker per file, for offline assignment models (ty/dupcensus.c); `TTTT_STEAL_BLOCK=1` steals blocks of files
- `TTTT_DEBUG_CONTAINERS=1` prints getSymbolChain's sorted candidate containers (module, specifier) and which one names each symbol: why an `import("...")` names one module rather than another
- `TTTT_DEBUG_EMIT_STORE=1` prints each declaration file a `-b` program puts into the emit store (`stored PATH for OWNER`), `=reads` also each one a later program read from it (`read PATH from OWNER`): which referenced projects' emitted declarations a program saw
- `TTTT_DEBUG_CYCLE=1` prints the chain of declarations/expressions whenever a declaration's type evaluation reaches itself (where TS7022-style circularity comes from)
- `TTTT_ORDER_STATS=1` counts union-order ties decided by type ids (by class); `TTTT_ORDER_SEED=N` permutes them, so diffing an oracle's output shows whether id order is observable
- `TTTT_DECLARATION_DIAGNOSTICS=1` keeps the declaration diagnostics (TS4xxx/TS9xxx) the CLI drops with noEmit when there are other errors (to audit drizzle); `TTTT_DEBUG_DECLARATION_TYPES=1` prints every inferred type the declaration walk prints
- `scripts/fastbuild.sh`: **the fastest tttt, always at `fast/tttt`** (today pgobuild.sh then boltbuild.sh; the script is the single definition of the pipeline, the path never changes); `--measured` prints the binary the measuring scripts use by default (fast/tttt since 2026-10-22: the laptop confirmed BOLT; the huge text page was removed on 2026-10-28)
- `scripts/pgobuild.sh`: the first step of the shipped build, `pgo/tttt` (LTO + PGO, -fno-plt), retrained (~3 min) only when the sources changed; `release/` (plain -O3) stays the edit-test build every other script uses
- `scripts/boltbuild.sh`: `pgo/tttt` relaid out by llvm-bolt (instrumented on pgobuild.sh's training set, hot functions and blocks packed, cold blocks split out), `bolt/tttt`, rebuilt (~1 min) only when pgo/tttt changed; same code, so byte-identical output. The front-end lever: agents/notes/code_layout.md
- `scripts/cgrank.py --run CORPUS [--bin B]` / `cgrank.py OUT [--lines [-f FUNC]] [--callers FUNC -e EVENT]`: cachegrind (simulated caches) at K1, functions or lines ranked by a stall estimate, callgrind callers (who memsets fresh memory): agents/notes/checker_speed.md has the ranking. Cachegrind models neither prefetch nor kernel page zeroing, so confirm with instructions and wall
- `scripts/inlinedup.py --run CORPUS` / `inlinedup.py OUT [--hot N]`: hot inlined copies ranked by hot instructions (callgrind at K1 against DWARF abstract origins), for the code-footprint work (`agents/notes/code_layout.md`)
- `scripts/instrcount.sh [--bin BUILD] [--save] [corpus...]`: instructions per corpus (single-threaded, the stable perf number to record when work lands; `--bin` an old build to bisect a regression; `--vs REV [--fast]`: release/tttt against `abbuild.sh REV`'s, both measured, the A/B of a change). Each is printed against `test/instrcount.txt` and a change over 2% is flagged: **investigate a flagged rise before committing** (a +50% on drizzle once went unnoticed for two days); `--save` updates the file
- `scripts/abbench.sh [-n N] OLD NEW CORPUS...`: two tttt binaries A/B at the defaults, interleaved, `TTTT_SYNC_EXIT=1`: medians of wall, sys, user, minor faults and peak RSS per corpus (copy `fast/tttt` out with `cp -L` before rebuilding). `scripts/exittail.py N CMD...`: start, last output byte and exit of a command, so the exit tail the reaper hides can be measured
- `scripts/bench.sh [--bun PATH]`: Perf benchmark against tsgo (and Bun's `bun check`, measurements.md says how to get it) (wall time, peak RSS, tttt phase split). `scripts/arenasites.sh -p DIR`: binder and checker arena bytes and types by allocating call site; `scripts/memtrack.sh -p DIR`: the malloc heap (the AST) per phase by allocating function, with its share of zero words. `scripts/survivors.sh -m MB -p DIR`: at each checker recycle, what declaration-level roots reach in the arena (measurements.md "A copying checker recycle") Rerun and update `agents/measurements.md` after perf-relevant changes. `tttt --time` prints each phase's time and resident set, and the checker's arena size and type count.
- `scripts/checkerdiff.py [-k K] [corpus...]`: tttt's diagnostics with `--checkers K` against one checker on the corpora (byte-identical: tsgo's output doesn't depend on K) and K twice byte-identical. `baseline_tests --checkers K --dump DIR` does the same for the suite (diff against a K=1 dump). `scripts/threadcheck.sh [corpus...]`: the corpora's output must be byte-identical at `--threads 1` and 4 (threads default to the cores, `--checkers` to one per thread but at most one per 16 KB of checked source; pass `--checkers 1` to compare with the suite's one checker). Both fetch corpora only when one is missing (`TTTT_NO_ENSURE=1`: an error instead, for worktrees) and pass the environment (`TTTT_SHARED_GRAPH=1`) through
- `scripts/tscbaseline.sh path/to/file.ts [types|symbols|errors.txt]`: Prints what tsc (tsgo 7.1) says about a file (the expected side of `scripts/filetest.sh`), handy when writing probes. `scripts/tsgoprobe.sh DIR` baselines a whole directory of test files at once (~40 ms each) (a test over `TTTT_PROBE_TIMEOUT` s, default 120, is reported, set aside and the rest rerun: exit 3, no baselines for it; `owntests.sh` then fails that test and keeps its old baselines); `scripts/tsctypeat.sh TSCONFIG FILE LINE NAME` prints tsgo's type of an identifier inside a real project
- `agents/notes/tsgo_map.md`: tsgo checker/binder/parser function -> tttt C function(s) and file, by subsystem (~370 rows, every C name verified): look a tsgo rule up there before grepping `src/` for its counterpart
- `scripts/run.sh path/to/file.ts`: Runs the typechecker as a user would. This produces type errors, but not the detailed information of the tests. It also doesn't run tsc against the file, so generally the test scripts are more useful

Tests are split into three test components, errors, symbols and types. A test component passes if tttt is able to annotate the input code the exact same ways as tsc. In the test output ` - ` marks a passing test component and `ERR`/`SYM`/`TYP` marks a failing one. In the diffs you get from failing tests, removed lines are lines tttt erroneously produced, and added lines are lines tttt failed to produce.

## Code Guidelines
tttt uses [cleat](https://codeberg.org/sphi/cleat) as its standard library, vendored at [thirdparty/cleat](thirdparty/cleat/). Cleat provides containers, strings, error handling, logging, filesystem access and subprocesses, and comes with its own vendored copy of the [STC](https://github.com/stclib/STC) container library. Cleat's own documentation is in [thirdparty/cleat/docs](thirdparty/cleat/docs/) and STC's is in [thirdparty/cleat/stc/docs](thirdparty/cleat/stc/docs/).

`src/prelude.h` pulls in `cleat.h` and is included directly or indirectly in all files. Between them you get, among other things:
- `#define my me->` (from cleat): This allows writing `my foo.bar` instead of `me->foo.bar` in functions that take a pointer argument `me`. This is the preferred style for method-like functions (`me`/`my` is used instead of `this` or `self`)
- `panic("message ", str, " ", num);` (from cleat): Immediately aborts the program with a message to stderr, if running under Valgrind a stack trace is printed to stderr as well, and the source location is a clickable link. `panic_if(condition, ...)` is the conditional form
- `check(condition)` (from cleat): Panics if condition is false, used for sanity checks
- `impossible` (from cleat): Panics if hit, used in places control flow should never hit
- `log_error("message ", str, " ", num)` (from cleat): Used for recoverable errors that do not require aborting, but should nonetheless never happen once the program is complete. `log_warn()`/`log_info()`/`log_debug()` are also available for print debugging, but note that `logger_config.threshold` hides anything below info by default

All of these take a [display](thirdparty/cleat/docs/display.md) sequence rather than a format string.

The project was originally a cleanroom implementation (I didn't read tsc other than tests). that rule is no longer in play but I still recommend paying more attention to what tsc observably does than how it does it.

## Project Structure
Feel free to change code in `src/` as much as you want, you can always revert it with git. Do not change code in `thirdparty/`, but you can look at it or anything you can find to understand what's going on; if a vendored library genuinely needs a fix, add a `thirdparty/*patch.txt` alongside the existing ones so `thirdparty/refresh.sh` reapplies it after a re-download. In particular `thirdparty/typescript/tsc/internal` (tsgo's Go sources) may be enlightening, as this is what we're reimplementing.

Refer to `documentation.md` for a description of the overall architecture of the C code base in `src/`.

Good luck, and have fun!
